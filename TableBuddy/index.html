WHY

CSV / Excel 的三个老问题

CSV / Excel 本身没问题。问题是当它同时承担「数据源 + 编辑界面 + 同步载体 + 程序上下文」时， 缺少字段校验、版本管理与可被调用的接口。

NO VALIDATION

没有字段约束

4O 与 40 从难分辨。列类型、必填、取值范围全靠人眼，脏数据静默入库。

FRAGILE

易误删与格式漂移

直接改文件，一次误操作就可能删错行；编码乱码、列名走样、BOM 与分隔符问题都难回溯。

NO API

无法被程序调用

想让看板、脚本或 AI 助手读这份数据，只能反复「导出再导入」，没有稳定的机器接口。

01

导入

拖曳文件即可导入 CSV / Excel，自动识别 UTF-8 与 GBK，推断列类型并建为物理数据表。

02

维护

在数据对话框里组合筛选、分页浏览、增删改行，并可与源文件双向同步。

03

消费

开启数据服务后，内置 Web 服务把数据表开放为 REST 接口，或封装成看板应用。
